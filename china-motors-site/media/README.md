# media/ — видео главного экрана

Здесь лежит один файл: `hero-loop.mp4` — короткий зацикленный кадр площадки,
который играет фоном hero на главной. Кадра в репозитории пока нет: снять его
может только тот, кто стоит на площадке.

## Как включить

Файл кладётся сюда под именем `hero-loop.mp4`, и в `index.html` у элемента
`<video class="v2-hero__video">` проставляется путь:

```html
data-src="media/hero-loop.mp4"
```

Пока `data-src` пустой, скрипт удаляет элемент и не делает ни одного запроса —
главная работает ровно так же, как до появления видео.

## Требования к съёмке

* **10–20 секунд.** Кадр зациклен, шов виден: снимать надо так, чтобы конец
  сходился с началом — ровная панорама, а не движение «туда и обратно».
* **Без звука.** Он всё равно не прозвучит: `autoplay` разрешён браузерами
  только для `muted`, и дорожка в файле — просто лишние килобайты.
* **Композиция под текст.** Поверх кадра лежат заголовок, подзаголовок и две
  кнопки, прижатые к левому нижнему углу, плюс общий скрим. Техника должна
  жить в правой половине и выше середины: CSS кадрирует видео как
  `object-position: center 40%`.
* **Без резких склеек и вспышек.** Фон, а не ролик; движение в кадре должно
  быть медленным.

## Как готовить файл

Целевой размер — **до 2 МБ**. Больше — и на мобильном интернете видео начнёт
конкурировать с фотографиями каталога.

```sh
ffmpeg -i source.mov \
  -t 16 \
  -vf "scale=1280:-2,fps=25" \
  -c:v libx264 -profile:v high -level 4.0 -pix_fmt yuv420p \
  -crf 30 -preset slow \
  -g 50 -keyint_min 25 -sc_threshold 0 \
  -movflags +faststart \
  -an \
  media/hero-loop.mp4
```

Что здесь важно и почему:

| Флаг | Зачем |
| --- | --- |
| `scale=1280:-2` | 720p хватает: кадр лежит под скримом и растянут `object-fit: cover`. Полноразмерный файл в hero не нужен. |
| `-crf 30` | Настройка качества под фон. Если файл вышел больше 2 МБ — поднимать до 32–34, а не резать длительность. |
| `-profile:v high -level 4.0`, `-pix_fmt yuv420p` | H.264 в том виде, который проигрывают все браузеры и iOS. |
| `-movflags +faststart` | Заголовок файла уезжает в начало, иначе браузер не начнёт проигрывание, не скачав файл целиком. |
| `-an` | Дорожки звука нет вовсе. |
| `-g 50 -sc_threshold 0` | Ключевой кадр каждые две секунды — зацикливание не даёт рывка на стыке. |

Проверить, что получилось:

```sh
ffprobe -hide_banner media/hero-loop.mp4     # длительность, кодек, битрейт
ls -lh media/hero-loop.mp4                   # размер
```

## Что делает страница, если файла нет

Ничего особенного — и это устроено намеренно. Фотография площадки осталась и
фоном секции (`.hp-hero` в `style-v2.css`), и постером самого `<video>`.
Видео лежит поверх неё прозрачным и проявляется только по событию `playing`.
Поэтому все отказы выглядят одинаково — на экране остаётся фотография:

* включено `prefers-reduced-motion: reduce`;
* включена экономия трафика или сеть определилась как 2G;
* браузер не проигрывает H.264;
* файл не отдался, не декодировался, автовоспроизведение запрещено политикой.

Отдельной обработки ни один из этих случаев не требует.
